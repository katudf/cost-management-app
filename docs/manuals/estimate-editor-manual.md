## 1. 新しい見積書を作る

見積書は「見積」タブの一覧画面（`EstimateList`）から作成します。

- **新規作成**: 一覧画面の「新規作成」ボタンを押すと、まっさらな見積エディタが開きます。顧客・工事名などはすべて未入力の状態から始まります。
- **複製**: 似た内容の見積書がすでにある場合は、一覧の行にある「複製」操作を使うと、既存の見積書の内容（明細行・設定を含む）をコピーした状態で新しい見積書として開けます。ゼロから作るより早く済むケースが多いです。

**使い分けの目安**: 過去に似た工事の見積書があるなら複製、まったく新しい内容なら新規作成、と考えてください。

## 2. 下書きの自動保存について

見積エディタは入力中に自動保存の仕組みを持っています。ただし、範囲と挙動を正しく理解しておく必要があります。

- 自動保存は**ブラウザのローカル（端末内）**に対して行われます。サーバー（Supabase）に自動送信されているわけではありません。
- そのため、同じ端末・同じブラウザで作業を再開した場合は、下書き復元ダイアログから直前の入力内容を呼び戻せます。
- 一方で、**別の端末やブラウザに切り替えると、ローカルの下書きは引き継がれません。** 正式にデータを残したい場合は、必ず「保存」ボタンを押してサーバーに保存する必要があります。
- 保存の保持期間や上限件数など、ローカル下書きの詳細な仕様（何日残るか、何件まで保持されるか）は資料からは確認できません。作業を中断する際は、こまめに「保存」を押してサーバー側に確定させることをおすすめします。

## 3. 明細行の入力・削除

明細は「シート」という単位でページ分割されます（1シートあたり19行）。

- 行の追加・削除・複製・リンクなどの操作は、行にカーソルを合わせたときに表示される**ホバー専用のツールバー**から行います。常時表示ではないため、慣れるまでは行の上にマウスを置いて操作アイコンを探す必要があります。
- **シートの削除**はシート一覧（左ナビゲーション `PageNav`）のゴミ箱アイコンから行います。削除確認のダイアログが表示され、「この操作は保存するまで元に戻せます」という案内が出ます。つまり、誤ってシートを削除しても、**保存ボタンを押す前であれば元に戻せる可能性があります**（画面をリロードして下書きを復元する、など）。
- シート0（先頭のシート）は削除できない仕様になっています。

## 4. 保存後の扱いと承認ワークフロー

- 「保存」ボタンはあくまで見積書のデータをサーバーに保存する操作です。これと、見積書のステータスを「申請中」などに進める操作は**別の操作**です。混同しないよう注意してください。
- ステータスを進める操作（承認ワークフローに乗せる操作）は、保存とは別のアクションとして用意されています。うっかり押し間違えないよう、特に申請中に進める操作の前には内容を見直すことをおすすめします。
- 承認・差戻しなど、権限によって操作できる・できないが分かれる部分がありますが、権限のないボタンがどのように表示されるか（グレーアウトされるか非表示になるか）の詳細は資料からは確認できません。

## 5. トラブルシューティング

### 保存ボタンを押してもエラーになる場合

保存できない場合、以下の5点のいずれかに該当している可能性が高いです。まずこれらを確認してください。

1. 顧客が選択されていない
2. 工事名が入力されていない
3. 見積番号の形式が正しくない（`YYMMDD-NNNN-NNN` 形式である必要があります）
4. 明細行数が300行を超えている
5. 見積番号が既存のものと重複している

このうち5番（番号重複）については、自動的に枝番を採番し直して解決できる救済機能があります。それ以外の1〜4は、入力内容を見直すことで解決できるはずです。

なお、エラーメッセージがどこまで具体的に原因を示してくれるか（「顧客が未選択です」のように直接教えてくれるかどうか）は資料からは確認できません。まずは上記5点を確認する、という手順を覚えておくと安心です。

### 明細行やシートを誤って削除してしまった場合

- **保存する前**であれば、削除は元に戻せる可能性があります（シート削除の確認ダイアログにもその旨が明記されています）。画面をリロードして下書き復元を試す、などの方法が考えられます。
- **保存した後**に明細の内容だけを誤って消してしまった場合、明細単位でのUndo（元に戻す）機能があるかどうかは資料からは確認できません。この場合は、詳しい人（先輩・開発担当）に確認するのが確実です。
- 見積書そのもの（レコード全体）を誤って削除してしまった場合は、一覧画面の**ゴミ箱機能**から復元できます。削除後**30日以内**であれば復元可能です。

### 迷ったときの基本方針

| 状況 | 対処 |
|---|---|
| 保存前のミス（行・シート削除など） | リロード・下書き復元で自己解決できる可能性が高い |
| 保存前のエラー（保存ボタンが効かない） | 上記5点セルフチェックでほぼ自己解決できる |
| 見積書ごと削除してしまった | ゴミ箱機能（30日以内）で復元 |
| 保存後に明細内容だけ誤って消した | 資料に手段の記載なし。詳しい人に確認 |

## 6. 用語ミニ辞典

| 用語 | 意味 |
|---|---|
| 鑑（かがみ） | 見積書の表紙部分。顧客・工事名・見積番号などを記載 |
| シート | 明細を記載するページ単位。1シート19行 |
| 下書き自動保存 | ブラウザのローカルに保存される一時データ。サーバー保存とは別物 |
| ゴミ箱機能 | 削除した見積書を30日以内なら復元できる機能 |

## 次回の修正内容（対話から見つかった改善提案）

このマニュアルを作成する過程で、インストラクター役・利用者役の対話から、UIやドキュメントだけでは解決しづらい問題点が複数見つかりました。実装の改善候補として記録します。

> **実装状況**: 以下は `ecstatic-cerf-0e582d`（branch `claude/quotation-editor-redesign-a3edb5`）ワークツリーで対応中。完了した項目には✅を付記します（未コミット）。

1. ✅ **「新規作成」ボタンの視認性・使い分け案内が不足**
   一覧画面の「新規作成」ボタンが目立たず、「複製」との使い分けがUI上で説明されていない。初めて使う人は両者の違いに迷う可能性がある。ツールチップやヘルプテキストでの案内を検討。
   → `src/EstimateList.jsx` の「新規作成」ボタンに `title` ツールチップ（「まったく新しい見積書を白紙から作成します」）を追加し、ヘッダー下に「似た見積書がある場合は一覧の『複製』が早く作成できます」という常時表示のヘルプテキストを追加。

2. ✅ **下書き自動保存の保存範囲・期限がUIに表示されていない**
   「ローカルにしか保存されない」「別端末では引き継がれない」という重要な制約が、画面上のどこにも明示されていない。保存インジケーター（例:「この端末に自動保存済み」)などの表示を追加すると安心感が増す。
   → `EstimateEditor.jsx` に `lastDraftSavedAt` state を追加し、デバウンス自動退避（1.5秒）が実行されるたびに更新。ヘッダーバーに「この端末に自動保存済み（◯分前）」という常時表示インジケーターを追加し、`title` ツールチップで「この端末のブラウザにのみ一時保存されています。別の端末では復元できません。正式に保存するには『保存』ボタンを押してください。」と明示。

3. ✅ **行操作ツールバーがホバー専用で発見しにくい**
   削除・複製・リンクなどの行操作アイコンがマウスホバー時にしか表示されないため、特にタッチデバイスや不慣れなユーザーには発見しづらい。右クリックメニューや常時表示の操作列など、代替の導線を検討する価値がある。
   → `SheetPaper.jsx` の行操作ツールバー（`RowToolbar`）を `opacity: 0`（完全非表示）から `opacity: 0.35`（常時薄く表示）に変更し、`pointer-events` も常時有効化。ホバーに加えて `:focus-within` でも `opacity: 1` になるようCSSを追加し、キーボード操作でも発見・操作できるようにした。あわせて `PageNav.jsx` のシート削除アイコンも `opacity-0` から `opacity-60`（常時ある程度視認可能）に変更。タッチデバイス（ホバー不可）でも存在に気づけるようにした。右クリックメニュー化は紙面レイアウトへの影響が大きいため今回は見送り。

4. ✅ **「保存」と「ステータスを進める（申請中にする等）」の違いが伝わりにくい**
   両者が別操作であることがUI上で区別しにくく、誤操作のリスクがある。申請中へ進める際の確認ダイアログの追加や、権限のないユーザーに対する承認/差戻ボタンのグレーアウト表示を検討。
   → 調査の結果、「申請中にする」（`EstimateSubmitModal`）と「承認/差し戻し」（`EstimateApprovalModal`）はすでに確認モーダル経由で、権限のないユーザーには非活性化＋ツールチップ（「指名された承認者のみ操作できます」）も実装済みだった。一方で「提出済にする」（`onSubmitToCustomer`）と「受注」（`onOrder`）の2ボタンだけは確認なしの一発実行になっていたため、`SettingsPanel.jsx` に `ConfirmModal`（`variant="primary"`）を追加し、この2操作をワンクッション挟むよう変更。確認メッセージには「これは見積データの保存とは別の操作です」という文言を明記し、保存とステータス進行の違いを明示。「受注」については差し戻しできない一方向の操作である旨も追記した。

5. ✅ **保存前と保存後で「取り消し可能かどうか」の境界が見えない**
   シート・行削除は保存前なら元に戻せるとされているが、保存後に明細の内容を誤って上書き・削除した場合の救済手段（変更履歴やUndo）がない。見積書単位のゴミ箱機能と同様に、明細データにも簡易な変更履歴（直前の保存内容へ戻せる機能）があると、ユーザーの不安を大きく減らせると考えられる。
   → サーバー側の正式な変更履歴（DBテーブル追加）は今回の修正範囲としては大きすぎるため見送り、ブラウザローカルの簡易救済機能を追加した。`estimateDraftV2.js` に「直前の保存内容スナップショット」を追加し、DB保存が成功するたびに（下書き自動退避とは別キーで）header/sheets/itemsを3日間保持する。`EstimateEditor.jsx` のヘッダーバーに「直前の保存内容に戻す」ボタン（`History`アイコン、スナップショットが存在する場合のみ表示）を追加し、押すと`ConfirmModal`（`variant="primary"`）で確認のうえ画面上の内容を直近の保存時点に戻せるようにした。戻した後は改めて「保存」を押すまでDBには反映されない旨をメッセージで明示。あくまでこのブラウザ内・3日間限定の簡易救済であり、正式な変更履歴機能ではない。

6. ✅ **保存エラー時のメッセージが原因箇所を明示しているか不明**
   保存をブロックする条件（顧客未選択・工事名未入力・見積番号形式・行数超過・番号重複）は決まっているが、エラーメッセージがどの条件に該当したかをユーザーに分かりやすく伝えているか（該当項目へジャンプする等）は実装側で確認が必要。
   → `EstimateEditor.jsx` の `handleSave` を調査した結果、メッセージ自体は元から条件ごとに個別だったが、(a) 顧客未選択・工事名未入力のメッセージが「顧客を選択してください」など簡潔すぎて、どこを直せばよいか（鑑のどの欄か）が明示されていない、(b) 該当欄が画面外にスクロールしていても自動で画面移動しない、という2点の改善余地があった。対応として、両メッセージを「顧客が選択されていません。鑑（表紙）の『顧客』欄で選択してください。」のように該当欄名を明記する文言に変更し、あわせて `scrollToCover()` ヘルパーを追加して鑑（`#paper-cover`）へ自動スクロールするようにした。見積番号形式エラー・番号重複エラーのメッセージにも「右側の設定パネルで確認してください」「『再採番』ボタンで別の番号を自動採番できます」という導線の説明を追記。行数超過エラーは元から上限値と現在値を明示しており、変更不要と判断した。

## 1. 目的

見積書の編集を「印刷される見積書と同じ画面」で直感的に行えるようにする（Excelで編集してそのまま印刷されるイメージ）。現行の `EstimateForm.jsx` ベースのフォーム型エディタを **完全置き換え** する。

## 3. 確定した設計判断（インタビュー結果）

1. **空行もデータとして保持** — 行タイプに空行を追加（コメント行と同じセンチネル方式）。`sort_order`＝行位置。ページ割りは19行/ページで機械的に導出
2. **カテゴリ(A/B/C)は行タイプとして温存、必須は撤廃** — 「各カテゴリに明細1件以上」バリデーションを廃止。過去見積はそのまま開ける
3. **階層内訳シートを参照リンク付きでフルサポート** — 子シート/カテゴリの合計を親行の単価に自動反映
4. **既存エディタは完全置き換え** — 旧 `EstimateForm.jsx` 系コンポーネントは最終的に削除。既存データは互換読込
5. **鑑画面: A4横の紙を中央に描画＋右サイド設定パネル** — 非印刷項目（ステータス操作・保存・トグル類）はパネルへ。税率・NET設定は紙面の合計ボックス付近クリックでも編集可（オーバーレイ併用）
6. **縦スクロール連続表示＋左ページナビ** — 鑑→明細シート…を縦に連ね、左端のページ一覧でジャンプ。ページ追加は最終シート下の［＋ページ追加］
7. **見積番号は現行形式を維持** — `YYMMDD-NNNN-NNN` 自動採番・重複チェック・枝番運用そのまま
8. **合計とリンクの統一ルール**（下記 §4）＋**総括表自動生成**ボタン
9. **19行/ページを維持**（現行PDFと同一。Excel時代の25〜26行には合わせない）
10. **Excelライク編集はレベル2まで** — セル直接編集、Tab/Enter/矢印移動、行挿入・削除・上下移動・空行挿入、**Excelからの複数セルTSV貼り付け**。範囲選択・フィルハンドルはスコープ外（将来拡張）
11. **現行踏襲項目** — ステータスワークフロー/編集ロック/承認RPC/受注時Projects連携、明示保存＋localStorage下書き(1.5sデバウンス)、PDF出力は `EstimatePDF.jsx`（シートモデル対応に改修）、▲/NET/コメント行の表示規約、顧客新規登録・明細取込(ImportItemsModal)・複製・ゴミ箱、PC前提

## 4. 合計とリンクの統一ルール

- **シート＝1つの「見積内訳明細書」**。複数ページにまたがれる（ページ割りは19行単位で自動）
- 各シートは末尾に合計行を持つ: トップシートは「**税抜合計**」、サブシートは「**合 計**」表記
- **カテゴリはシート内のセクション**。末尾に「合 計」行（カテゴリ小計）を置ける。カテゴリで改ページはしない
- **行のリンク先は2種類**:
  - ①別シートの合計 → 自行の**単価**に反映（③千歳橋型。摘要に「明細書No.n」自動表示）
  - ②カテゴリ合計 → 数量1.0式・単価に反映、名称も連動（②水沢中型）
- **シート1がトップシート**: 税抜合計＝工事金額（税抜）として鑑の工事金額・消費税相当額・合計(税込)に自動反映
- 安全費・法定福利費（FIXED行）・NET行・※注記はトップシート末尾に配置
- ①単純型は「シート1だけ」の特殊ケースとして自然に成立（＝最終ページ下部に税抜合計）
- **総括表自動生成**: 明細シートのカテゴリ一覧から総括シート（②のP2形式）をワンクリック生成し、以後リンクで連動

## 5. データモデル

### 新テーブル `estimate_sheets`
| カラム | 型 | 説明 |
|---|---|---|
| id | uuid PK | |
| estimate_id | FK → estimates **ON DELETE CASCADE** | |
| sort_order | int | シート順（1=トップシート） |
| title | text null | シート名（画面表示・ページナビ用） |

※ RLSポリシーを `estimate_items` と同等に設定すること（設定漏れは既定拒否で全操作が失敗する）。

### `estimate_items` 追加カラム
| カラム | 型 | 説明 |
|---|---|---|
| sheet_id | uuid FK → estimate_sheets null | 所属シート（null=トップシート帰属として読込） |
| linked_sheet_id | uuid FK → estimate_sheets null | ①シート合計リンク |
| linked_category_item_id | **bigint** FK → estimate_items null | ②カテゴリ合計リンク（既存 `estimate_items.id` は bigint） |

- 空行: `item_type:'item'` ＋ センチネル（コメント行 `__comment__` と同方式、例 `category_symbol:'__blank__'`）
- 循環参照はクライアント側でチェック（リンク作成時に到達可能性検査）＋ RPC側で最低限の自己参照ガード
- 既存見積のマイグレーション: 見積ごとに `estimate_sheets` を1行生成し、全 `estimate_items.sheet_id` に設定（1トランザクション＋件数検証）

### 保存方式とIDの安定化（重要）
現行 `save_estimate_items` RPC は delete+insert 方式のため、保存のたびに行 `id` が振り直され、`linked_category_item_id` の参照先が保存ごとに消滅する。対策:

- 旧RPCは温存し、**`save_estimate_items_v2` を新設**（旧エディタ・Excel取込は移行完了まで旧RPCで稼働）
- v2 は**2パス方式**: クライアントはリンクを配列インデックス（一時キー）で送り、RPC が INSERT 後に新 `id` へ再マップして `linked_category_item_id` を確定する
- シートは delete+insert せず **UPSERT** して `sheet_id` / `linked_sheet_id` を安定させる
- 複製 (`duplicateEstimate`) はシート複製＋旧→新IDの再マップ表を `sheet_id` / `linked_sheet_id` / `linked_category_item_id` の3列に適用する

### 既存データ互換
- `sheet_id IS NULL` の行は読込時にトップシートへ帰属（移行期に旧エディタ・Excel取込が書いた行も開ける）
- DBに保存済みの旧 `subtotal` 行はカテゴリ「合 計」行として読み替える
- 物理削除RPC `purge_expired_estimates` はシートのCASCADE削除で整合（estimate_id FK に ON DELETE CASCADE）
- localStorage 下書きは `SCHEMA_VERSION` を 2 に更新（旧v1下書きは復元対象外になる点に留意）

## 6. 画面構成

```
┌──┬───────────────────────┬─────────┐
│ペ │   A4横の紙（鑑）        │ 設定パネル │
│ｌ │   ─────────────        │ ・ステータス│
│ジ │   A4横の紙（明細シート1 │ ・保存/PDF │
│ナ │    ページ1..n）         │ ・税率/NET │
│ビ │   [＋ページ追加]        │ ・トグル類 │
└──┴───────────────────────┴─────────┘
```

- 印刷される項目は紙の上で直接インライン編集（WYSIWYG）
- 明細グリッド: 19行固定枠。セル編集、キーボードナビ、行操作、TSV貼り付け
- 承認済み等のロック時は紙全体を読み取り専用表示（現行の `isLocked` 踏襲）

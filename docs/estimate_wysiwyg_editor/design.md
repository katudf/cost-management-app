## 3. 確定した設計判断（インタビュー結果）

1. **空行もデータとして保持** — 行タイプに空行を追加（コメント行と同じセンチネル方式）。`sort_order`＝行位置。ページ割りは19行/ページで機械的に導出
2. **カテゴリ(A/B/C)は行タイプとして温存、必須は撤廃** — 「各カテゴリに明細1件以上」バリデーションを廃止。過去見積はそのまま開ける
3. **階層内訳シートを参照リンク付きでフルサポート** — 子シート/カテゴリの合計を親行の単価に自動反映
4. **既存エディタは完全置き換え** — 旧 `EstimateForm.jsx` 系コンポーネントは最終的に削除。既存データは互換読込
5. **鑑画面: A4横の紙を中央に描画＋右サイド設定パネル** — 非印刷項目（ステータス操作・保存・トグル類）はパネルへ。税率・NET設定は紙面の合計ボックス付近クリックでも編集可（オーバーレイ併用）
6. **縦スクロール連続表示＋左ページナビ** — 鑑→明細シート…を縦に連ね、左端のページ一覧でジャンプ。ページ追加は最終シート下の［＋ページ追加］
7. **見積番号は現行形式を維持** — `YYMMDD-NNNN-NNN` 自動採番・重複チェック・枝番運用そのまま
8. **合計とリンクの統一ルール**（下記 §4）＋**総括表自動生成**ボタン
9. **19行/ページを維持**（現行PDFと同一。Excel時代の25〜26行には合わせない）
10. **Excelライク編集はレベル2まで** — セル直接編集、Tab/Enter/矢印移動、行挿入・削除・上下移動・空行挿入、**Excelからの複数セルTSV貼り付け**。範囲選択・フィルハンドルはスコープ外（将来拡張）※その後、セルの範囲選択（消去・コピー・貼り付け）を追加（§6）
11. **現行踏襲項目** — ステータスワークフロー/編集ロック/承認RPC/受注時Projects連携、明示保存＋localStorage下書き(1.5sデバウンス)、PDF出力は `EstimatePDF.jsx`（シートモデル対応に改修）、▲/NET/コメント行の表示規約、顧客新規登録・明細取込(ImportItemsModal)・複製・ゴミ箱、PC前提

## 4. 合計とリンクの統一ルール

- **シート＝1つの「見積内訳明細書」**。複数ページにまたがれる（ページ割りは19行単位で自動）
- 各シートは末尾に合計行を持つ: トップシートは「**税抜合計**」、サブシートは「**合 計**」表記
- **カテゴリはシート内のセクション**。末尾に「合 計」行（カテゴリ小計）を置ける。カテゴリで改ページはしない
- **行のリンク先は2種類**:
  - ①別シートの合計 → 自行の**単価**に反映（③千歳橋型。摘要に「明細書No.n」自動表示）
  - ②カテゴリ合計 → 数量1.0式・単価に反映、名称も連動（②水沢中型）
- **シート1がトップシート**: 税抜合計＝工事金額（税抜）として鑑の工事金額・消費税相当額・合計(税込)に自動反映
- 安全費・法定福利費（FIXED行）・NET行・※注記はトップシート末尾に配置
- ①単純型は「シート1だけ」の特殊ケースとして自然に成立（＝最終ページ下部に税抜合計）
- **総括表自動生成**: 明細シートのカテゴリ一覧から総括シート（②のP2形式）をワンクリック生成し、以後リンクで連動

## 5. データモデル

### 新テーブル `estimate_sheets`
| カラム | 型 | 説明 |
|---|---|---|
| id | uuid PK | |
| estimate_id | FK → estimates **ON DELETE CASCADE** | |
| sort_order | int | シート順（1=トップシート） |
| title | text null | シート名（画面表示・ページナビ用） |

※ RLSポリシーを `estimate_items` と同等に設定すること（設定漏れは既定拒否で全操作が失敗する）。

### `estimate_items` 追加カラム
| カラム | 型 | 説明 |
|---|---|---|
| sheet_id | uuid FK → estimate_sheets null | 所属シート（null=トップシート帰属として読込） |
| linked_sheet_id | uuid FK → estimate_sheets null | ①シート合計リンク |
| linked_category_item_id | **bigint** FK → estimate_items null | ②カテゴリ合計リンク（既存 `estimate_items.id` は bigint） |

- 空行: `item_type:'item'` ＋ センチネル（コメント行 `__comment__` と同方式、例 `category_symbol:'__blank__'`）
- 循環参照はクライアント側でチェック（リンク作成時に到達可能性検査）＋ RPC側で最低限の自己参照ガード
- 既存見積のマイグレーション: 見積ごとに `estimate_sheets` を1行生成し、全 `estimate_items.sheet_id` に設定（1トランザクション＋件数検証）

### 保存方式とIDの安定化（重要）
現行 `save_estimate_items` RPC は delete+insert 方式のため、保存のたびに行 `id` が振り直され、`linked_category_item_id` の参照先が保存ごとに消滅する。対策:

- 旧RPCは温存し、**`save_estimate_items_v2` を新設**（旧エディタ・Excel取込は移行完了まで旧RPCで稼働）
- v2 は**2パス方式**: クライアントはリンクを配列インデックス（一時キー）で送り、RPC が INSERT 後に新 `id` へ再マップして `linked_category_item_id` を確定する
- シートは delete+insert せず **UPSERT** して `sheet_id` / `linked_sheet_id` を安定させる
- 複製 (`duplicateEstimate`) はシート複製＋旧→新IDの再マップ表を `sheet_id` / `linked_sheet_id` / `linked_category_item_id` の3列に適用する

### 既存データ互換
- `sheet_id IS NULL` の行は読込時にトップシートへ帰属（移行期に旧エディタ・Excel取込が書いた行も開ける）
- DBに保存済みの旧 `subtotal` 行はカテゴリ「合 計」行として読み替える
- 物理削除RPC `purge_expired_estimates` はシートのCASCADE削除で整合（estimate_id FK に ON DELETE CASCADE）
- localStorage 下書きは `SCHEMA_VERSION` を 2 に更新（旧v1下書きは復元対象外になる点に留意）

## 6. 画面構成

```
┌──┬───────────────────────┬─────────┐
│ペ │   A4横の紙（鑑）        │ 設定パネル │
│ｌ │   ─────────────        │ ・ステータス│
│ジ │   A4横の紙（明細シート1 │ ・保存/PDF │
│ナ │    ページ1..n）         │ ・税率/NET │
│ビ │   [＋ページ追加]        │ ・トグル類 │
└──┴───────────────────────┴─────────┘
```

- 印刷される項目は紙の上で直接インライン編集（WYSIWYG）
- 明細グリッド: 19行固定枠。セル編集、キーボードナビ、行操作、TSV貼り付け（範囲を選ばずに複数セルを貼ると、カーソルのある列から 品名→仕様→数量→単位→単価→摘要 の並びで流し込み、行が足りなければ追加。金額欄からは摘要へ、工種行・コメント行では行わない）
- 承認済み等のロック時は紙全体を読み取り専用表示（現行の `isLocked` 踏襲）
- No. 欄: 明細行に1から連番。工種小計リンク行（リンク②。総括表の行など）は連番の代わりに参照先の工種記号（A・B…）を出し、番号を消費しない（`sheetRowLayout.buildLinkSymbolLabeler`。全シートの工種行から id・_tempId・_uid で引くので、明細側で記号を変えれば追従。画面とPDFで共通）。参照先の記号が空なら連番で数える
- 見積一覧の「PDFプレビュー・印刷」（エディタを開かずに出すPDF）は `savedEstimatePdfData.buildPdfEstimateFromSaved` で、保存済みの明細をシートごとに振り分け、計算エンジンでリンク①②・シート合計を解決し、`encodeSheetItemsForOutput` で工種小計・コメント行を整えてから出力する（エディタのPDFプレビューと同じ内容になる）
- 入力途中のデータの自動退避（`estimateDraftV2.js`）: 編集中の鑑・シート・明細を1.5秒ごとにこの端末の localStorage へ退避（見積ごと・新規は共通で1件、7日で失効）。開いたときに退避が残っていれば、確認画面ではなく紙面の上に帯（［復元する］［破棄］）を出し、編集は止めない。提案する前回分は別キー（`estimate-draft-v2:<id>:pending`）へ移すので、帯の表示中も新しい入力は通常のキーへ退避でき、前回分は上書きされない。前回分と通常の退避が両方残っていれば（帯を出したまま編集して閉じた）前回分から順に提案。編集後、または前回分が開いたときの保存日時（`updated_at`）より古いときの［復元する］は確認を挟み、後者は帯にも「保存済みの内容の方が新しい」と出す。保存成功で両方を消し、「破棄して戻る」は通常の退避だけを消す（未判断の前回分は次に開いたとき再び提案）。退避の中身が保存済みの内容と同じ（`isDraftSameAsContent`。ステータス・承認の記録と行の識別子は比べない）なら提案せずに捨てる。ステータス操作・承認・差し戻しで鑑に反映するサーバーの値は「未保存の変更」にしない（反映した鑑と同じ参照で、シート・明細も変わっていない描画だけを除外）
- 元に戻す／やり直し（`editHistory.js` / `useEditHistory.js`）: 鑑・シート・明細の `{header, sheets, items}` を操作単位で履歴化（最大100件、画面を開いている間のみ、保存後も保持）。同じセル・同じ鑑項目への連続入力は1件にまとめ、別の入力欄へ移ると区切る。紙面上では Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z）がブラウザ標準の入力Undoより優先。右パネル上部にボタン（ツールチップに操作名）。行・シート削除、総括表生成、貼り付け、明細取込、直前の保存内容に戻す の後は「元に戻す」付きの通知を出す。ステータス・承認・案件連携の項目は戻さない。ロック中は無効。シート削除の確認ダイアログは維持
- 複数行の一括操作（`rowBulkOps.js`）: 行の左端のつまみをクリックで選択（Shift: 範囲／Ctrl: 追加・解除）。選択は1シート内に限る。先頭の選択行の上に操作バー（上下移動・複製・コピー・切り取り・削除・解除）。キーは Delete／Ctrl+C・X・V／Alt+↑↓／Esc。貼り付けは選択行（セルにカーソルがあればその行）の下へ挿入し、工種行・コメント行・空行も種類を保つ。クリップボードには Excel 用のタブ区切り（セル貼り付けと同じ列順）と行データ（html の data-estimate-rows）を入れる。リンク行は同じ見積で参照先が現存し循環しない場合のみリンクを残し、それ以外はコピー時点の値で固定。シートの全行を削除したら空の明細行を1行残す。セルへの入力開始・Esc・ロックで選択解除。切り取った工種行を同じ見積へ貼ると元の識別子を引き継ぎ、②リンクを保つ
- 行のドラッグ移動（`rowBulkOps.moveRowsTo`）: 左端のつまみをドラッグ。選択行をつかめば選択行をまとめて、それ以外はその1行。行の上半分なら前・下半分なら後ろへ（青線で表示）、行以外の場所はシート末尾。別シートへも移せ、行は識別子を保ったまま所属シートだけ変わるのでリンクは切れない。左ナビのシート名へ落とすとそのシートの末尾。画面の上下端で自動スクロール。新たに循環参照が生じる移動は行わず通知する。移動元シートが空になれば空の明細行を1行残す。1回のドラッグ＝元に戻す1回
- セルの範囲選択（`cellRangeOps.js`）: Shift+クリック、セルをまたぐマウスドラッグ、Shift+↑↓ で選ぶ（セル内のドラッグと Shift+←→ は文字選択のまま）。範囲は1シート内・長方形で、行の選択とは同時に持たない。列は 品名・仕様・数量・単位・単価・金額・摘要。操作は Delete（範囲を空にする。行は消さない）、Ctrl+C（見えている値を Excel 用のタブ区切りで。工種行・コメント行は品名列だけ値を持つ）、Ctrl+V（1つの値なら範囲全体へ、複数セルなら範囲の左上から範囲の中だけに入れ、はみ出しは捨てる。範囲が大きくても繰り返さない。行は挿入しない）。数量・単価を変えた行は金額を再計算し、金額列への指定はそれより優先。書き込めないセル（リンク①の単価・金額・摘要、リンク②の品名・数量・単位・単価・金額、工種行・コメント行の品名以外）は飛ばし、飛ばした数とはみ出した数を通知。この画面でコピーした行データを貼るときは範囲があっても従来どおり行を挿入。1回の消去・貼り付け＝元に戻す1回。文字の入力・移動キー・Esc・セル以外のクリック・ロックで範囲を解除。Ctrl+D とフィルハンドルは入れていない（コピーした1セルを範囲へ貼れば同じことができるため）。品名・単位の候補リストは Shift を押すと閉じ、リストの上での Shift+クリックは候補を確定せずに下のセルへの Shift+クリックとして扱う。数値欄はカーソルがある間も、範囲操作や元に戻すで値が変われば表示を更新する
- 品名の入力補完（DB関数 `search_estimate_item_suggestions`、`supabaseEstimates.searchEstimateItemSuggestions`）: 明細行の品名欄に2文字以上入力し0.3秒止まると、過去の見積明細から品名の部分一致で最大10件を候補表示。「品名＋仕様＋単位」ごとに一番新しい見積（発行日順）の単価と、使用回数・最終使用日を出す。並びは最終使用日→使用回数。削除済み見積・工種行・コメント行・空行・リンク行は除外。選ぶと品名・仕様・単位・単価を上書きし金額を再計算（数量・摘要はそのまま、元に戻す1回で戻る）。SECURITY INVOKER のため明細を読めるロールにだけ結果が返る
- 単価の一括調整（`priceAdjustOps.js` / `PriceAdjustDialog.jsx`）: 右パネルの［単価の一括調整］と、行選択の操作バーから開く。対象は「選択中の行」（行の選択、またはセル範囲に含まれる行。開いた時点の選択）／各シート／全シートから選び、初期値は選択があれば選択中の行、無ければ最後にカーソルを置いたシート。掛率（％）を掛け、端数は単位（1円・10円・100円）と方法（切り捨て・四捨五入・切り上げ）を選ぶ（前回の選択をブラウザに保存）。単価のある行は単価に掛け、金額が数量×単価の自動計算なら計算し直し、手で上書きした金額は金額にも掛けて同じ端数処理。単価が空で金額だけの行は金額に掛ける。マイナスの行（値引き等）とリンク行は変更せず、行数を通知。工種行・コメント行・空行は対象外。画面では変更する行数、対象の合計と見積合計（税抜）の調整前→調整後を表示（対象の選択肢の行数も変更できる行だけを数える）。掛率が50%未満・200%超なら打ち間違いの注意を出し、Enter では実行せずボタンでだけ実行する。画面を開いている間はカーソルを画面の外へ出さず、開いても行の選択は外さない。1回の調整＝元に戻す1回
